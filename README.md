# YTM → Discord

Показывает трек из вкладки YouTube Music в статусе Discord.
Десктопное приложение YTM не нужно, к гугл-аккаунту ничего не обращается.

```
music.youtube.com (вкладка)
   └── inject.js — читает mediaSession + <video>
        └── ws://127.0.0.1:8765
             └── bridge.py — троттлит и толкает в Discord IPC
```

## Установка в двух кликах

Скачать → распаковать не в Downloads → двойной клик по `install.command` →
загрузить папку `extension` в Chrome → вставить свой Application ID в попап.

## Требования

- macOS, Python 3.9+
- Discord **десктопный** (через веб-клиент IPC-сокета нет)
- Chrome

## Установка

**1. Распакуй проект не в Downloads.** Например в `~/ytm-discord` —
macOS ограничивает фоновые процессы в папке загрузок.

**2. Создай Discord-приложение.** discord.com/developers/applications →
New Application. Имя приложения = то, что увидят в статусе, так что
назови его `YouTube Music`. Скопируй **Application ID** (это не секрет,
Client Secret и Bot Token не нужны). В App Icon залей `app-icon-1024.png`
из архива, если нравится ящерица.

**3. Двойной клик по `install.command`.**

Откроется окно терминала, установщик всё сделает сам. macOS в первый раз
скажет, что файл из интернета и разработчик неизвестен — тогда правый клик
по файлу → **Открыть** → **Открыть** ещё раз в диалоге. Это разово.

Он создаст venv, поставит зависимости и зарегистрирует агента, который
стартует при входе в систему. В конце покажет лог — там должно быть:

```
[bridge] connected to Discord
[bridge] listening on ws://127.0.0.1:8765
```

**4. Поставь расширение.** `chrome://extensions` → Developer mode →
Load unpacked → папка `extension`.

**5. Вставь Application ID.** Клик по иконке расширения в панели Chrome →
поле внизу попапа → Сохранить. Затем обнови вкладку YouTube Music.

**6. Включи трек.**

## Управление

Клик по иконке расширения в панели Chrome — тумблер и поле Application ID. Выключение гасит
статус сразу, перезагружать вкладку не нужно.

Пауза в плеере тоже убирает статус.

## Команды

```bash
tail -f ~/Library/Logs/ytmbridge.log                      # смотреть лог
launchctl kickstart -k gui/$(id -u)/com.local.ytmbridge   # перезапустить
launchctl bootout gui/$(id -u)/com.local.ytmbridge        # выключить совсем
```

После правки `bridge.py` перезапуск обязателен — агент держит старый код
в памяти.

## Если не работает

**Пусто в логе** — Discord не запущен или запущен только в браузере.

**`[bridge] listening`, но треков нет** — расширение не загрузилось или
вкладка YTM открыта с прежнего сеанса. Перезагрузи карточку расширения,
потом вкладку через Cmd+R. Второй шаг обязателен: скрипт работает в
контексте страницы и переживает перезагрузку расширения.

**Статус не гаснет по тумблеру** — та же причина, обнови вкладку.

**В логе `waiting for an Application ID`** — ID не сохранён в попапе,
либо вкладка YTM не перезагружена после сохранения.

**Обложка не грузится** — Discord капризен к внешним URL. Убери
`large_image` из payload в `bridge.py`.

## Устройство

Источник и транспорт разделены намеренно. Данные берутся из
**MediaSession API**, а не из вёрстки страницы, поэтому редизайны
YouTube ничего не ломают. Та же схема с заменой одного `matches`
в манифесте ляжет на SoundCloud, Bandcamp, Deezer — они тоже
заполняют mediaSession.

Discord принимает обновление присутствия примерно раз в 15 секунд,
поэтому прогресс-бар рисуется не пушами, а парой timestamps
`start`/`end`, отданной один раз.
